## EPIC 7 — Dashboard

### 7.1 — Conectar a la API real

**Problema:** el Dashboard usa `MOCK_DATA` completo, no `dashboardService.getSummary()`.

**Groundwork listo:** `dashboardService.getSummary()` ya devuelve `DashboardSummary` (tipado real del backend). `src/types/dashboard.types.ts` expone `DashboardTotals`, `VacancyStatusBreakdownItem`, `MonthlyActivityItem`.

**Pasos:**

1. Cargar al montar:
   ```ts
   const [summary, setSummary] = useState<DashboardSummary | null>(null);
   const [loading, setLoading] = useState(true);
   useEffect(() => {
     dashboardService.getSummary()
       .then(setSummary)
       .catch(console.error)
       .finally(() => setLoading(false));
   }, []);
   ```
2. Mapear la respuesta:
   - **Métricas (`MetricCard`):** de `summary.total` → Total Posiciones=`positionsCount`, Departamentos=`departmentsCount`, Candidatos=`candidatesCount`, Vacantes Abiertas=`openVacanciesCount`.
   - **Estados de vacantes:** de `summary.vacancyStatusBreakdown[]` (`status`, `count`, `percentage`). Mapear `ACTIVE/PAUSED/CLOSED` a label ("Abiertas/Pausadas/Cerradas") y color. Puede transformarse a `DashboardVacancyStatusCard[]` (interfaz UI existente).
   - **Gráfica mensual:** de `summary.monthlyActivity[]` — `month` ("2026-01" → "Ene"), `positionsCreated`, `cvUploads`, `vacanciesCreated`. Calcular `MAX_Y_VALUE` dinámicamente (hoy fijo en 14).
3. Estados de carga/error/empty (hoy no hay).

**✅ Criterio:** métricas y gráficas con datos reales del usuario.

## EPIC 8 — Panel de Administración

Archivos: `src/pages/AdminPanel.tsx`, `src/components/admin/*`, `src/types/admin.types.ts`, nuevo `src/services/api/admin.api.ts`.
API: §6 — **admin-only** (`role: ADMIN`, si no `403`).

### 8.1 — Crear el servicio `admin.api.ts`

Los endpoints admin **no** usan `sendResponseOr404`, así que `apiClient` desempaqueta `.data` normal.

```ts
import { apiClient } from "./apiClient";
import { User } from "../../types/api.types";

interface AdminStats {
  usersCount: number;
  candidatesCount: number;
  positionsCount: number;
  vacanciesCount: number;
  activeVacancies: number;
  closedVacancies: number;
}

interface AdminUsersPage {
  users: User[];
  meta: { totalCount: number; currentPage: number; totalPages: number };
}

export const adminApi = {
  getStats: (): Promise<AdminStats> =>
    apiClient<AdminStats>("/admin/stats", { method: "GET" }),

  getUsers: (page = 1, limit = 50): Promise<AdminUsersPage> =>
    apiClient<AdminUsersPage>(`/admin/users?page=${page}&limit=${limit}`, { method: "GET" }),

  updateRole: (id: number | string, role: "ADMIN" | "USER"): Promise<User> =>
    apiClient<User>(`/admin/users/${id}/role`, {
      method: "PUT",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ role }),
    }),

  deleteUser: (id: number | string): Promise<void> =>
    apiClient<void>(`/admin/users/${id}`, { method: "DELETE" }),
};
```

### 8.2 — Conectar `AdminPanel` y módulos

**Problema:** hoy usan `mockUsers` (`UserTableModule.tsx:6`), loader `setTimeout`, y el buscador no tiene `onChange`.

**Pasos:**

1. Elevar el estado a `AdminPanel`: cargar `adminApi.getStats()` y `adminApi.getUsers()` al montar (quitar el `setTimeout`).
2. `StatsModule` recibe las stats reales; `UserTableModule` recibe `users` por props (no mock) y un `onChange` real para el buscador (filtrar por nombre/email en cliente).
3. `RoleUpdateModule` → `adminApi.updateRole(id, role)`; `UserDeleteModule` → `adminApi.deleteUser(id)`. Refrescar la lista tras cada acción.
4. Estados de carga/error/empty.

### 8.3 — Casing de roles

**Problema:** la API usa `ADMIN`/`USER`; `admin.types.ts` tipa `'admin' | 'user'`.

**Pasos:** unificar al enum del backend (`ADMIN`/`USER`) en `AdminUser.role` y en la UI mapear a etiqueta visible ("Admin"/"Usuario"). Ajustar los módulos de rol.

---

### 8.4 — No confundir stats globales con dashboard

`GET /admin/stats` es **global** (toda la plataforma); `GET /dashboard` es por usuario (§9.4). Mantenerlos como fuentes separadas; el panel admin usa `/admin/stats`. (Es principio de diseño; no requiere código si 8.1/8.2 respetan la separación.)

**✅ Criterio EPIC 8:** el panel lista usuarios reales (paginados), permite cambiar rol y eliminar, y muestra stats globales.
