## EPIC 3 — Arreglar el flujo de creación de Posición ✅ RESUELTO

**Resuelto en:** sesión previa + sesión actual.

- **3.1** — `Position.tsx` importa y usa `departmentsApi.getAll()`; estado tipado como `Department[]` (resuelve también P3 §10.4 en ese archivo).
- **3.2** — `positions.api.ts` envía el campo `pdf` en `POST /positions/complete`.
- **3.3** — el `<select>` de `educationLevel` usa los valores del enum (`NONE`, `HIGH_SCHOOL`, `TECHNICAL`, `BACHELOR`, `UNIVERSITY`, `MASTER`, `DOCTORATE`) con labels en español.
- **3.4** — renombrado `education` → `educationArea` en `CreatePositionInput` e `INITIAL_STATE`; `validateStep(4)` lo exige solo cuando `educationLevel` no es `NONE`/`HIGH_SCHOOL`; asterisco condicional en la label.

- **3.5** — `processWithAI` mapea `aiData.educationArea ?? prev.educationArea`.
  - **Fix adicional (sesión actual):** `aiData.yearsOfExperience ?? prev.yearsOfExperience` (antes era `||`, que descartaba el 0 legítimo).
- **3.6** — client-side: `role.trim().length >= 5`, `description.trim().length >= 25`, `technicalSkills.length >= 1`, `softSkills.length >= 1`, más `educationArea` condicional. El display de errores ahora surface los `details` de Zod campo por campo (`formatApiError`).

## Cómo verificar (regresión general)

1. `npm run dev`, login.
2. Crear 1 departamento, 1 posición (probar manual + IA con PDF de ≥300 caracteres), 1 vacante.
3. Entrar a `/position-history`, `/vacancy-history`, `/cv-history` → deben listar lo creado.
4. Editar la vacante → "Volver al historial" lleva a `/vacancy-history`.
5. Crear posición con `educationLevel: NONE` y `educationArea` vacío → 201 (backend asigna `"N/A"`).
6. Crear posición con `yearsOfExperience: 0` → 201 (backend actualizado 2026-07-08 para aceptar `>= 0`).
