### 4.3 — Estado de vacante inválido `FILLED` → `CLOSED`

```js
// Después

```
Revisar el copy del `alert` ("vacante cerrada") para que sea coherente.

### 4.4 — Pantalla de éxito con código real (no "Vac-009")

**Problema:** `VacancySuccess` usa `vacancyCode = "Vac-009"` por defecto y `Vacancy.tsx` no le pasa nada.

**Pasos:**
1. En `Vacancy.tsx handleSubmit`, capturar la respuesta de creación:
   ```ts

   setCreatedVacancy(created);          // nuevo estado

   ```
2. Guardar el id/código en estado (`const [createdVacancy, setCreatedVacancy] = useState<Vacancy | null>(null);`).
3. Pasar el código al componente:
   ```tsx

     vacancyCode={createdVacancy ? `Vac-${String(createdVacancy.id).padStart(3, "0")}` : undefined}

   />
   ```
4. (Consistencia) En modo edición no aplica crear; si se muestra éxito de edición, usar el `id` de la URL.

### ✅ Criterio de aceptación EPIC 4

Crear, editar y listar vacantes funciona; cambiar estado a "Cerrada" persiste; la pantalla de éxito muestra el código real de la vacante creada.

## EPIC 5 — Flujo de carga de CVs

API: §4/§5. **Los candidatos se crean SOLO vía `POST /vacancies/:id/upload`** (campo `pdfs`, máx 100, 5MB c/u, solo PDF). No existe `/api/uploads`.

### 5.1 — `UploadCV` apunta a un endpoint inexistente

**Problema:** `src/services/api/uploads.api.ts:12` hace `POST /uploads`, que **no existe**. La subida genérica sin vacante no es soportada por el backend.

**Decisión de diseño (recomendada):** convertir `/uploadcv` en "subir CVs **a una vacante**":

**Pasos:**
1. En `UploadCV.jsx`, cargar las vacantes al montar con `vacanciesApi.getAll()` y agregar un `<select>` de vacante destino (obligatorio antes de subir).
2. Reemplazar la llamada de subida:
   ```js
   // Antes
   await uploadService.uploadCVs(files);
   // Después
   await vacanciesApi.uploadCVs(selectedVacancyId, files);
   ```
   `vacanciesApi.uploadCVs` ya usa el campo correcto `pdfs` (`vacancies.api.ts:66`).
3. Bloquear el botón "Subir" si no hay vacante seleccionada.
4. Eliminar `src/services/api/uploads.api.ts` (o dejarlo deprecado) una vez migrado; ya no se usa.

**Alternativa mínima:** si por diseño no debe pedirse vacante aquí, eliminar la ruta `/uploadcv` y el acceso desde el sidebar, y mover "Añadir candidato" al detalle de la vacante. (Confirmar con el equipo cuál flujo se quiere.)

### 5.2 — Manejar la respuesta por archivo

**Contexto (§4):** el 201 devuelve un **array**; cada elemento es `{ success: true, data: Candidate }`, o `{ success: false, message, error, stack }`, o un candidato existente si el CV está duplicado (hash SHA-256). Un archivo fallido no bloquea a los demás.

**Pasos:**
- Tras subir, iterar el array de resultados y mostrar por archivo: creado / duplicado / fallido (con el `message`).
- No asumir éxito global: hoy la UI muestra un único "success". Cambiar a un resumen ("3 procesados, 1 duplicado, 1 con error").

### ✅ Criterio de aceptación EPIC 5

Subir uno o varios PDFs a una vacante crea candidatos asociados y la UI reporta el resultado por archivo (incluyendo duplicados y errores).

**Pasos:**
```js

```
