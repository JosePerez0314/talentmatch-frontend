## EPIC 10 — UI/UX and code quality

### 10.1 — Unify candidate statuses across screens

**Problem:** two different vocabularies, and neither matches the backend:

- `src/components/ui/StatusDropdown.jsx:9` → `["No contratado", "Contratado", "Contactar"]`
- `src/pages/AdvancedResults.tsx:8,92` → `["No Contratado", "Contactado", "Contratado"]`
- The API's real enum (§5) → `DISPONIBLE | CONTRATADO`

They differ in wording ("Contactar" vs "Contactado") and casing ("No contratado" vs "No Contratado").

**Steps:**

1. Define a single label set (derived from the backend enum) in a shared place (e.g. `src/types` or a constant).
2. Replace the literals in `StatusDropdown.jsx` and `AdvancedResults.tsx`.
3. Align with the **P1 §6.3** decision (if candidate status doesn't persist, adjust the copy so it doesn't imply saving).

**✅ Criterion:** a single candidate-status vocabulary across the app.

### 10.2 — Show/hide password icon is inverted

**File:** `src/components/ui/LoginForm.tsx` (~line 60).

Today: password visible → `Eye` (open); hidden → `EyeOff`. The usual convention is the opposite (open eye = "show" while it's hidden).

**Fix:**

```tsx
{showPassword ? <EyeOff className="w-5 h-5" /> : <Eye className="w-5 h-5" />}
```

**✅ Criterion:** password icon follows the correct convention.

### 10.6 — Import types instead of redeclaring them

`src/pages/EvaluationsHistory.tsx` locally defines the `EvaluationVacancy` interface (with the comment "Declaramos la estructura aquí mismo para solucionar las líneas rojas de TypeScript"), when `src/types/evaluations.types.ts` already exports an identical one. Import it from there.

**✅ Criterion:** one source of truth per type.

### 10.7 — Dead dependencies in `package.json`

`express`, `cors`, and `dotenv` are declared as `dependencies` of a 100% client-side frontend. Same for `react-router` alongside `react-router-dom` (which already pulls it in). Uninstalling them shrinks the dependency tree and removes confusion about the architecture.

**✅ Criterion:** `package.json` reflects only what the code imports.
