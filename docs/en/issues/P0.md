## EPIC 1 — Normalize the response envelope in `apiClient` ✅ RESOLVED

**Resolved in:** a previous session (see [`../last-changes.md`](../last-changes.md)).

- `apiClient.ts` normalizes the `sendResponseOr404` double-wrapping (`{ response: { success, data } }`) by unwrapping `response` first and then `data`.
- Tolerance for `success: "false"` (string) was removed after the backend fix (2026-07-07, see [`../api-documentation.md`](../api-documentation.md) §9.2).
- **1.2 (ad-hoc extractors):** removed from `PositionHistory.tsx`, `VacancyHistory.tsx`, `Vacancy.tsx` (`posRes`), and validated in `CVHistory.jsx`. `Position.tsx` now uses `departmentsApi.getAll()` (see EPIC 3.1).
- **1.3 (regression):** login (`{ success, token, user }` with no `data` → returns the envelope), vacancy edit (`GET /vacancies/:id` without double wrapping), and flat 201 creations: all verified.

## EPIC 3 — Fix the position creation flow ✅ RESOLVED

**Resolved in:** a previous session + the current one.

- **3.1** — `Position.tsx` imports and uses `departmentsApi.getAll()`; state typed as `Department[]` (this also resolves P3 §10.4 in that file).
- **3.2** — `positions.api.ts` sends the `pdf` field on `POST /positions/complete`.
- **3.3** — the `educationLevel` `<select>` uses the enum values (`NONE`, `HIGH_SCHOOL`, `TECHNICAL`, `BACHELOR`, `UNIVERSITY`, `MASTER`, `DOCTORATE`) with Spanish labels.
- **3.4** — renamed `education` → `educationArea` in `CreatePositionInput` and `INITIAL_STATE`; `validateStep(4)` only requires it when `educationLevel` is not `NONE`/`HIGH_SCHOOL`; the asterisk on the label is conditional on the same rule.
  - **Additional fix:** the payload sends `educationArea: undefined` when the value is empty, so `JSON.stringify` omits it and the backend assigns `"N/A"` (§8.1). It previously sent `""` and Zod returned a 400.
- **3.5** — `processWithAI` maps `aiData.educationArea ?? prev.educationArea`.
  - **Additional fix:** `aiData.yearsOfExperience ?? prev.yearsOfExperience` (it was `||`, which discarded a legitimate `0`).
- **3.6** — client-side: `role.trim().length >= 5`, `description.trim().length >= 25`, `technicalSkills.length >= 1`, `softSkills.length >= 1`, plus the conditional `educationArea`. Error display now surfaces Zod `details` field by field (`formatApiError`).

## How to verify (general regression)

1. `npm run dev`, log in.
2. Create 1 department, 1 position (test manual + AI with a PDF of ≥300 characters), 1 vacancy.
3. Visit `/position-history`, `/vacancy-history`, `/cv-history` → they must list what you created.
4. Edit the vacancy → "Volver al historial" takes you to `/vacancy-history`.
5. Create a position with `educationLevel: NONE` and an empty `educationArea` → 201 (the backend assigns `"N/A"`).
6. Create a position with `yearsOfExperience: 0` → 201 (backend updated 2026-07-08 to accept `>= 0`).
