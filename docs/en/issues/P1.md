## EPIC 5 — CV upload flow

### 5.2 — Per-file detail in the upload response

**Current state:** `UploadCV.jsx` counts how many files failed and shows "N de M archivo(s) no pudieron procesarse". The per-file detail is missing.

**Context (§4):** `POST /vacancies/:id/upload` returns an array where each element is:

- `{ success: true, data: Candidate }` — new CV processed.
- `{ success: true, data: <existing candidate> }` — duplicate CV (SHA-256 hash already existed).
- `{ success: false, message, error, stack }` — processing failure.

See `UploadResult` in `src/types/api.types.ts`.

**Pending:**

- Pass `results: UploadResult[]` to the `UploadCVSuccess` component.
- Show, per file: created / duplicate / failed (with the `message` on failure).
- Change the current copy ("N documentos subidos") to a summary like "3 processed, 1 duplicate, 1 error".
- **Note on duplicates:** the backend responds `{ success: true, data: <existing candidate> }` when the hash already exists. Detecting exact duplicates requires comparing `hash` (there is no flag). In a first iteration, assume "created" whenever `success: true`; adjust if a flag is added later.

**✅ Criterion:** uploading a mixed batch (new CVs + duplicates + a bad file) reports the exact result per file.

### 6.3 — Candidate status has no backend (design decision)

**Context (§5):** candidates are read-only; there is no endpoint to change their individual status. Real enum: `DISPONIBLE | CONTRATADO`.

**Problem:** the results `StatusDropdown` (`Resultados.jsx` + `CandidateMatchRow`) implies candidate status is persisted, but only the **vacancy** status has an endpoint.

**Decision (pick one):**

- **(a) Recommended** — Remove the per-candidate status control and keep only the "Contratar" action, which closes the vacancy (already done in the "Contratado" flow → `PATCH /vacancies/:id/status` → `CLOSED`).
- **(b)** Keep the control as a local visual filter, making it clear that it does not persist (not recommended — it confuses).

Align the labels with §5 (`DISPONIBLE`/`CONTRATADO`) — this also unblocks P3 §10.1.

**✅ Criterion:** no controls that fake persisting candidate status; document the decision.
